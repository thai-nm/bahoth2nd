# 07 — UI

Target: "clean, readable, atmospheric" — not fancy, not a wireframe. The look
comes from a restrained palette, good typography, and layered shadows, not
from illustration we cannot afford.

## 7.1 Screens

```
Home ──create──▶ Room lobby ──host starts──▶ Game ──▶ Result
  └──join code──▶
```

| Screen         | Contents                                                                                                                                                                                                        |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Home**       | Name field, Create Game, Join with code. Restores the last seat token if one exists and offers "rejoin".                                                                                                        |
| **Room lobby** | Seat list with connection dots, explorer picker (12 portraits, one per colour selectable), room settings (turn timer, unimplemented-haunt policy), Start (host only, needs 3+ seats and all characters chosen). |
| **Game**       | The main layout, below.                                                                                                                                                                                         |
| **Result**     | Winner banner, final board, full event log, "play again" which creates a new room and invites the same seats.                                                                                                   |

## 7.2 Game layout

Desktop, 1280×800 and up:

```
┌───────────────────────────────────────────────────────────────┐
│ TOP BAR  room code · phase · whose turn · omens drawn · timer  │
├──────────┬──────────────────────────────────────┬─────────────┤
│ PLAYERS  │                                      │  LOG        │
│          │           BOARD VIEWPORT             │             │
│ portrait │   (pan/zoom, floor tabs top-right)   │  scrolling  │
│ 4 trait  │                                      │  event      │
│ tracks   │                                      │  narration  │
│ items    │                                      │  + chat     │
│  ×N      │                                      │             │
├──────────┴──────────────────────────────────────┴─────────────┤
│ ACTION BAR   move · use item · attack · trade · end turn      │
└───────────────────────────────────────────────────────────────┘
```

- **Players rail** (left, 240px): one card per explorer. The local player's
  card is pinned to the top and expanded. Trait tracks render as the printed
  8-slot strip with a marker — not as a number — because that is how players
  reason about them and it makes "you lost 2 Might" legible.
- **Board viewport** (centre, flexible): see 7.3.
- **Log** (right, 300px, collapsible): event narration generated from
  `GameEvent`s, interleaved with chat. Dice rolls render as their actual faces.
- **Action bar** (bottom): only ever shows actions returned by
  `getLegalActions`. Illegal actions are hidden, not disabled-with-a-tooltip,
  except for the two most confusing cases (attack before the haunt; move with
  0 movement left) which stay visible and disabled with a reason.

Tablet landscape: the log collapses into a drawer. Phone: supported but
degraded — board full-screen, everything else in bottom sheets. Do not spend
milestone time here before M5.

## 7.3 Board rendering

Absolutely positioned DOM tiles inside a transformed container.

```
<div class="viewport">                     // overflow hidden, wheel/drag handlers
  <div class="world" style="transform: translate(px,py) scale(k)">
    <div class="tile" style="transform: translate(x*T, y*T) rotate(r)"> … </div>
    …
    <svg class="overlay"> doors, links, movement highlights </svg>
    <div class="token" …>explorer pawns, monsters</div>
  </div>
</div>
```

- `T` = tile size in px, fixed at 120. Zoom is the container's `scale`.
- One `.tile` per placed tile. Rotation is a CSS transform on the tile's
  background layer only — **the room name label counter-rotates so it stays
  upright**, matching how people actually read the physical board.
- Pan: pointer drag on empty space. Zoom: wheel / pinch, clamped to 0.4–2.0.
  "Fit floor" and "centre on me" buttons, because players get lost.
- **Floor tabs** (Basement / Ground / Upper) switch which floor is rendered.
  The tab for a floor containing another player who just moved gets a pulse.
  Inactive floors are not rendered at all — no reason to keep them mounted.
- Movement: clicking a highlighted room issues `MOVE`. Clicking an
  unexplored doorway arrow issues `MOVE_THROUGH`. Reachable rooms come from
  `getReachable`, so the highlight can never disagree with the server.
- Discovery flow: the new tile animates in at 0 opacity/0.9 scale; if a
  rotation prompt is pending, it renders semi-transparent with rotate
  left/right buttons and a confirm, and every other player sees "Ox is placing
  the Ballroom…".

### Tile appearance without art

Each tile renders as a rounded square with:

- a flat background colour derived from the tile's `art.bg` (content-provided)
- the room name in a serif face, centred, counter-rotated
- door notches drawn as SVG gaps in the border
- the card symbol as a corner badge (Item / Event / Omen have distinct
  glyph + colour)
- floor-restriction dots along the bottom edge

This is genuinely presentable, and swapping in real tile art later means
setting `art.image` in content and adding one `<img>` layer.

## 7.4 Key interactions

| Interaction         | Design                                                                                                                                                                                                  |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Card reveal**     | Centre-screen modal, card flips in, 2 s minimum before the dismiss button enables so nobody skips past what they drew. Other players see the same card in a smaller non-blocking toast.                 |
| **Dice roll**       | Modal with the dice tumbling ~700 ms, then final faces + total + what was needed. Result is already decided by the server; the animation is theatre and must never gate the action.                     |
| **Haunt roll**      | Same, but full-width and tense: shows `total` vs `omens drawn`, and on trigger the screen desaturates and the haunt reveal takes over.                                                                  |
| **Haunt reveal**    | Traitor gets a private full-screen panel with their instructions and a "I have read this" confirm. Heroes simultaneously get theirs. Neither can see the other's.                                       |
| **Attack**          | Select target in room → choose trait (if a card allows a variant) → both rolls animate side by side → loser gets a damage-allocation dialog with `+`/`−` steppers over their two eligible trait tracks. |
| **Trade**           | Drag items between the two players' item rows, or click-to-select on touch. Confirm sends one `TRADE` action.                                                                                           |
| **Pending prompts** | Whoever must answer sees a modal; everyone else sees a top-bar banner naming them and a countdown if a deadline exists. The game visibly waits on a person, never mysteriously.                         |

## 7.5 Visual design

- **Palette.** Dark UI chrome (near-black warm greys), parchment-toned board
  surface, one accent per player colour matching the six explorer colours.
  Traitor state introduces a desaturated red wash on the top bar after the
  haunt.
- **Type.** One serif for room names and card titles, one clean sans for UI.
  Two families, four weights, no more.
- **Motion.** 150–250 ms ease-out for everything except the deliberate
  theatre of dice and card reveals. Respect `prefers-reduced-motion` by
  cutting animation to instant transitions — the game must be fully playable
  with motion off.
- **Sound.** Deferred to M5. When added: dice, card flip, door, haunt sting.
  Off by default, one toggle.

## 7.6 Accessibility

Not gold-plating — most of it is free given DOM rendering:

- All actions reachable by keyboard; the board is a focusable grid with arrow
  navigation between explored rooms.
- Never encode information in colour alone. Player colours always pair with
  the explorer's name or initial; card symbols pair glyph with colour.
- The event log is an `aria-live="polite"` region, which makes the whole game
  followable by screen reader without extra work.
- Minimum 4.5:1 contrast on text; check the parchment board surface early,
  it's the one that will fail.

## 7.7 Client state and data flow

```
ws message ──▶ zod parse ──▶ zustand store
                                ├─ state: redacted GameState
                                ├─ version, seatId, roomCode, seats
                                ├─ outbox: unacked actions
                                └─ animQueue: GameEvent[]
                                        │
React components select from the store ─┘
```

- Components read via selectors; the engine's `getLegalActions` /
  `getReachable` are called during render from the store's state.
- `animQueue` is drained by a single effect that plays events in order and
  gates the next one on the previous animation's completion. This is why
  events exist separately from snapshots.
- **No component holds derived game state in local `useState`.** The only
  local state is transient UI (which modal tab is open, drag position).
